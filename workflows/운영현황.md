## 지역 확장 — 한 코드로 두 지역 (2026-08-02)

경기남부 상황판을 추가했다. **코드는 하나**고 '지역마다 다른 값'만 갈아끼운다.
지금까지처럼 화면·수집기를 통째로 복사했다면 앞으로 기능을 고칠 때마다 두 번 고쳐야 하고,
한쪽만 고치는 실수가 반드시 난다.

| | 경기북부 (운영) | 경기남부 (신규) |
|---|---|---|
| 주소 | gyeonggi-dashboard.visanu81.workers.dev | **weather.visanu81.workers.dev** |
| Cloudflare Worker | `gyeonggi-dashboard` | `weather` |
| 관할 | 10개 시군 · 11개 관서(고양/일산 분리) | 21개 시군 |
| 데이터 파일 | `data.js` | `data-south.js` |
| 지도 | `map-geo.js` | `map-geo-south.js` |
| 화면 설정 | `region.js` | `region-south.js` |
| 텔레그램 알림 | 보냄 | 안 보냄(북부 구독자에게 남부 특보가 가면 안 됨) |

**지역별 값이 사는 곳**
- 뒷단(수집): `tools/region_profiles.py` — 시군·격자·관측소·특보구역·하천·산불권역
- 앞단(화면): `region.js` / `region-south.js` — 관서 순서·배치도·행정명·중점 관서

**돌리는 법**
```
python tools/update_data.py                            # 경기북부 → data.js
python tools/update_data.py --profile south --no-push  # 경기남부 → data-south.js
python tools/update_data.py --push-only                # 커밋·푸시·배포 (마지막에 한 번)
```
서버 `update.sh`는 두 지역을 **동시에** 돌린 뒤 한 번만 푸시한다(순서대로 돌리면 5분을 넘김).
중복 실행 방지 lock도 걸어 뒀다.

**만드는 도구 (다시 뽑을 때)**
```
python tools/build_region_profile.py --verify                    # 북부 운영값 재현 검증
python tools/build_region_profile.py --build south --check-rivers # 남부 값 생성 + 하천 현실성 검사
python tools/build_map_geo.py --verify                            # 지도 생성기 검증
python tools/build_map_geo.py --profile south --merge --out map-geo-south.js
python tools/verify_profiles.py                                   # 북부 값이 안 바뀌었는지 대조
```
생성기는 모두 **경기북부 운영값을 그대로 재현하는지 먼저 검증**한 뒤 남부를 만든다.
재현이 안 되면 남부 값도 믿을 수 없다는 뜻이다.

**API 호출량** (5분 주기, 실측)
- 북부 51회/회차, 남부 71회/회차 → 하루 약 35,000건 (공공데이터포털분은 약 15,000건)
- 단기예보는 하루 8번만 발표되는데 5분마다 부르고 있었다 → 발표시각 기준 캐시로 97% 감축.
  덕분에 **지역이 둘로 늘었는데도 예전 북부 단독 때보다 호출이 적다.**

**주의**
- 남부에서 걸러낸 것: 김포 사우교 수위관측소(조위 영향으로 평상시에도 관심수위 초과 → 매일 주의 표시).
  `tools/build_region_profile.py`의 `RIVER_EXCLUDE` 참조.

### 상황실 상단바 '임진강 감시' 카드 (2026-08-04)

필승교·군남댐은 관서 순환과 무관하게 늘 봐야 하는 지점이라(필승교=북측 황강댐 무단방류
조기감지, 군남댐 방류량=하류 임진강 수위) 상단바에 **고정 카드**로 올렸다.
전에는 연천 차례가 돌아올 때만 보였다.

상단바 칸 배분 (무대 안쪽 폭 3728px)
```
전: 1120 | 1fr(1400) | 460 | 640                    ← 관서명·날씨가 내용보다 넓었음
후:  700 | 1fr(924)  | 860 | 460 | 640   (북부)
     700 | 1fr(1820) |     | 460 | 640   (남부 — 카드 없음)
```
칸이 좁아진 만큼 글자도 줄였다(관서명 150→118px, 기온 170→140px). 안 줄이면 `nowrap`이라 잘린다.

**어느 지점을 띄울지는 `region.js`의 `topRivers`가 정한다** — 한강홍수통제소 관측소 코드로
지정(표기명은 바뀔 수 있어도 코드는 안 바뀜). 비우면 카드가 사라지고 4칸으로 돌아간다.
남부는 비워 뒀다 — 넣고 싶으면 `region-south.js`에 코드만 적으면 된다.

구현은 `tools/wall-build/build_wall.py`의 `(k1)~(k5)` 패치. `design_clean.html`(사장님 디자인
원본)은 건드리지 않는다 — 디자인을 다시 받으면 수정이 날아가기 때문.

### 저장소 비대화 · 히스토리 압축 (2026-08-05 개선)

**문제** — 5분마다 데이터를 커밋하니 저장소가 하루 수백MB씩 커진다. 그래서 서버가
'커밋 300개 넘으면 히스토리를 1커밋으로 눌러 강제 푸시'하고 있었다(거의 하루 한 번).
이 압축은 공통 조상을 없애 **개발 PC의 클론에서 rebase가 불가능해진다** — 압축 커밋이
내 작업을 되돌리는 것처럼 보이는 충돌이 실제로 났다.

**실측한 1회차 커밋 비용 (약 1.6MB → 하루 460MB)**

| 파일 | 크기 | 비고 |
|---|---|---|
| `images/kma_satellite.png` | **907KB** | 전체의 57% |
| `data-south.js` | 358KB | |
| `data.js` | 269KB | |
| 레이더·강수예측·특보발효도 | 55KB | 합계 |

**고친 것 3가지**

1. **위성영상을 30분 주기로** (`tools/update_data.py`)
   천리안 위성은 **6시간 지연 공개** 자료다. 5분마다 받아 커밋할 이유가 없었다.
   파일이 30분 안 지났으면 건너뛴다 → **하루 커밋량 460MB → 240MB (절반)**.
   건너뛴 회차는 이전 이미지·메타를 그대로 쓰므로 화면은 그대로다.
   로그에 `갱신 주기 아님`으로 찍히니 장애로 오해하지 말 것.

2. **압축 판단을 '커밋 수' → '실제 .git 용량'으로** (`update.sh`)
   커밋 수는 용량의 대리지표일 뿐이라 디스크가 멀쩡해도 압축이 돌았다.
   이제 `.git`이 **1200MB**를 넘을 때만 압축한다(커밋 2000개는 백스톱).
   위 1번과 합쳐 **압축 주기가 하루 1회 → 약 5일에 1회**로 줄어든다.

3-1. **개발 PC 용량 회수** (`tools/dev_clean.sh`, 2026-08-11 추가)
   압축이 일어나도 개발 PC에 남은 옛 브랜치·작업폴더가 압축 전 히스토리를 붙들고 있어
   `.git`이 계속 커진다(실측 5.0GB — 대부분이 7월 이전 `staging` 브랜치 10,470커밋).
   ```
   bash tools/dev_clean.sh          # 무엇을 지울지 보여주기만
   bash tools/dev_clean.sh --run    # 실제 정리
   ```
   지우기 전에 브랜치마다 "origin/main 에 없는 파일"이 있는지 확인하고, 있으면 건너뛴다.
   바탕화면의 작업폴더(`기상,재난상황판-2`)는 **지우지 않고** 원격 최신으로 맞춘다.

3. **개발 클론 동기화 도구** (`tools/dev_sync.sh`)
   압축이 일어나도 rebase로 씨름하지 말 것. 코드의 정답은 언제나 `origin/main`이다.
   ```
   bash tools/dev_sync.sh          # origin/main 에 맞추기
   bash tools/dev_sync.sh --gc     # 맞춘 뒤 옛 객체 정리(용량 회수)
   ```
   커밋 안 한 변경이 있으면 멈추고, 되돌리기용 `dev-backup` 브랜치를 남긴다.

### 배포할 때만 커밋 (2026-08-11 개선)

위 항목의 '앞으로 더 줄이려면'을 실행한 것. 5분마다 커밋했지만 실제 배포는
20~40분에 한 번이라, 나머지 커밋은 **아무 화면에도 안 나가는 데이터**였다.

**바꾼 것**

1. `tools/update_data.py` — 배포 판단을 실행에서 분리(`deploy_decision`).
   `--push-only`는 이제 **배포하기로 결정한 회차에만** 커밋·푸시한다.
   배포 안 하는 회차의 변경은 파일로 남아 있다가 다음 배포 때 한 커밋으로 같이 올라간다.
   → 화면에 나가는 데이터는 그대로(배포 직전 회차가 항상 최신), 커밋 수만 1/4~1/8.

2. `update.sh` — 회차 시작의 `git reset --hard origin/main`을 **조건부**로.
   무조건 되돌리면 아직 커밋 안 한 데이터를 5분마다 지워버린다.
   이제 `origin/main`이 우리보다 앞서 있을 때(코드 배포·히스토리 압축)만 되돌린다.
   ```
   if ! git merge-base --is-ancestor origin/main HEAD; then git reset --hard origin/main; fi
   ```
   히스토리 압축 블록에도 `git add -A`를 넣었다 — 안 그러면 압축이 옛 데이터로 되돌린다.

3. 겸사겸사 **배포 판단이 두 지역을 같이 본다**. 배포 한 번이 북부·남부 사이트를
   같이 올리는데 판단은 북부 data.js만 보고 있었다. 남부에만 호우특보가 떠도
   최대 40분 늦던 것이 이제 즉시 나간다.

**주의** — 배포 사이에는 서버 작업트리가 '더러운' 상태로 보이는 게 정상이다
(`git status`에 data.js·이미지가 변경됨으로 뜸). 장애가 아니다.

### '⚠ N분째 갱신 없음' 배지 기준 (2026-08-11)

지도 화면 우하단의 빨간 배지는 **화면 데이터가 오래됐을 때** 뜬다(서버·회선 장애 감지용).
기준이 15분이었는데 **화면은 배포될 때만 바뀌고 그 주기가 평소 40분·급변특보중 20분**이라,
평상시에도 배지가 떠서 오경보가 됐다(2026-08-11 사장님 발견).

→ 기준을 **50분**으로 올렸다. 평소 최악 = 배포간격 40분 + 수집 3분 + 배포반영 2분 ≈ 45분,
여기에 경계 깜빡임을 막을 5분 여유. `지도.html`의 `dataStale` 참조.

⚠ **배포 주기(`deploy_decision`)를 당기면 이 값도 같이 내려야 한다.** 둘은 짝이다.
안 그러면 배지가 장애를 늦게 알린다.

참고 — 진짜 급한 특보·하천 위험은 화면이 아니라 **1분 주기 텔레그램 알리미**
(`tools/check_warnings.py`)가 담당한다. 화면 주기와는 별개 경로다.

## ★★ 상황실에 '가짜 호우 재난문자'가 떴던 일 (2026-08-15)

**사장님 신고** — "연천에 호우주의보가 떴다는데 확인해줘."

**사실** — 기상청엔 경기북부 호우특보가 **0건**이었다(그날 전국 호우주의보는 제주도산지 1곳).
그런데 상황실 동두천 화면에 이런 재난문자가 떠 있었다:

> 동두천시 · 호우 · 13:36 — "**호우주의보 발효.** 하천변·지하공간·지하주차장 접근을 금지하고…"
> 경기도 · 호우 · 12:40 — "시간당 **1.1mm의 강한 비**가 내리고 있습니다…[경기도청]"

**원인** — `design_clean.html`(사장님이 Claude Design에서 받은 시안)은 시연용으로
**비가 오면 재난문자를 지어낸다.** 실데이터를 아예 안 본다.
```js
if (s.wet){ msgs = [ {text:'호우주의보 발효. …'}, {text:'시간당 '+s.rain1h+'mm의 강한 비…'} ]; }
else      { msgs = ((EXT().msgs || MSGS)[s.name] || …) }   // ← 실데이터는 여기만
```
문자 없는 관서에 샘플이 뜨는 건 이미 막아뒀지만(`msgs`에 전 관서 키를 빈 배열로 채움),
**이 분기는 `EXT().msgs`를 거치지 않아서 그 방어를 그냥 통과했다.**
"1.1mm의 강한 비"라는 말이 안 되는 문장이 가짜라는 결정적 단서였다.

**조치** — `build_wall.py`에 패치 (j7) 추가. 강수 여부와 무관하게 **항상 실제 재난문자만**
쓰고, 없으면 안 띄운다. 겸해서 문자 종류별 색을 넣었다(호우=파랑, 강풍=주황).

**교훈 — 디자인 시안의 '지어낸 값'은 전부 봉인 대상이다.**
시안은 그림이 예뻐야 해서 데이터를 만들어낸다. 운영에선 그게 거짓말이 된다.
새 디자인을 받으면 **반드시 아래를 훑을 것**:

| 확인할 것 | 방법 |
|---|---|
| 값을 지어내는 분기 | `design_clean.html`에서 `EXT()`를 안 거치는 대입, `Math.random`, `rnd(`, `r1~r3` |
| 샘플로 폴백하는 자리 | `\|\| MSGS`, `\|\| RIVERS`, `\|\| RISKS`, `\|\| REGIME` |
| 폴백이 실제로 막혔는지 | 브라우저에서 `WALL_DATA`의 `stations·rivers·msgs·risks·warns`에 **전 관서 키가 다 있는지** |

2026-08-15 점검 결과 — 네 묶음 모두 11개 관서 키 전부 존재(폴백 차단됨), `stations`도 11개.
재난문자가 마지막 구멍이었다.

### ① 시군 기온이 2~3시간씩 얼어붙어 있었다 (가장 컸던 것)

단기예보 캐시가 맞는 회차(=5분 주기의 약 97%)마다 `UnboundLocalError: items`로 죽었다.
`items`는 '캐시를 안 쓴 회차'에만 만들어지는데 뒤쪽 일최고/최저 루프가 그걸 썼다.
죽으면 호출부가 '수집 실패'로 보고 직전 값을 되살리므로, **시군 기온·습도가 예보
발표시각(하루 8번) 사이에 그대로 멈춰** 있었다. 실측: 의정부 05:10~07:11 22.8° 고정.

**왜 아무도 몰랐나** — `updated`는 매 회차 새로 찍혀서 화면상 정상으로 보이고,
'⚠ N분째 갱신 없음' 배지도 안 뜬다. 한 번만 호출해 보면 절대 안 보이는 버그다.
→ `by_time`(양쪽 경로에 다 있는 자료)으로 순회하도록 수정. 회귀 점검 추가.

### ② 경기남부에 광주광역시 특보가 섞였다

특보 지역판정이 `f'{reg_up_ko} {reg_ko}'`에 관할 시군명이 **글자로 들어있는지**만 봤다.
관할에 '광주'(경기 광주시)가 있어 광주**광역시**의 '광주동부·광주서부'(L1130xxx)가
통째로 관할로 잡혔다. 광주광역시에 호우경보가 나면 경기남부 상황실에 호우경보가 뜬다.
→ 이름이 아니라 **특보구역 코드**로 판정(`reg_map`이 정본). 경기 육상은 전부 L101xxxx.

### ③ 상황실 벽면의 풍향이 난수였다

풍속·순간풍속은 실측인데 풍향만 관서번호 기반 의사난수(`Math.round(r3*360)`)였다.
실제 풍향은 데이터에 이미 있었다(AWS `wds`, 기상청 실황 `vec`) — 안 쓰고 있었을 뿐.
→ `build_wall.py` 패치 (j8). 자료가 없으면 '—'로 비우고 화살표도 숨긴다
(null을 그대로 넣으면 원본 계산식이 '북'으로 둔갑시킨다).

### ④ 남양주·구리가 산불 권역에서 빠져 있었다

수집단(`fire_sigun_map`)엔 있는데 표시용 묶음(`fire_groups`)에서만 빠져서,
값을 받아놓고 버리고 있었다. 운영 data.js의 `fire`가 4건(=8개 시군)뿐이었다.

### ⑤ 검사기가 거짓 합격을 내고 있었다 (이게 제일 무서운 것)

`tools/verify_profiles.py`는 '리팩터링 직전 update_data.py'를 git에서 꺼내 북부 상수를
대조하는 구조였는데, **서버의 히스토리 압축으로 그 원본이 사라져 북부 검사 11개가 전부
'건너뜀'** 이 된 채 마지막에 '전부 통과'를 출력하고 있었다. 아무것도 검사하지 않고
합격을 내는 검사기였다(이 세션에서 여러 번 '전부 통과'로 보고된 것이 이 상태였다).

→ 다시 만들었다:
- 사라진 원본에 의존하지 않는 **구조 무결성 점검**을 두 지역 모두에 적용
- 건너뛴 항목이 있으면 절대 '전부 통과'라고 하지 않음
- `--api` 로 외부 API 회귀 점검(①의 '두 번 연속 호출', ②의 지역판정)

```
python tools/verify_profiles.py          배포 전 필수(오프라인)
python tools/verify_profiles.py --api    + 실호출 회귀 점검
```

**이 검사기가 위 ②③④를 실제로 잡는지 일부러 되돌려 시험했다** — 넷 다 잡았다.
앞으로 이 부류(관측소 누락·기준수위 역전·다른 광역 코드 혼입·권역 누락)는 배포 전에 걸린다.

**남은 경고 1건** — 북부 구리는 관내 수위관측소가 없다. 남부는 생성기가 12km 이내
'인근' 관측소를 붙였는데 북부는 손으로 만들어서 안 붙었다. 검사기가 매번 경고로 알린다.
